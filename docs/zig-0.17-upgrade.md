# Coordinated Zig upgrade

## Compiler policy

The official download index lists Zig 0.17.0 as the latest stable release. The development branch is 0.18.0-dev. These upgrades target exactly 0.17.0.

Use stable Zig on default branches. Keep old tags available for older compilers. Add an older compiler branch only if someone commits to supporting it. A minimum compiler version is a floor, not a promise that future Zig releases will work.

There is no single Zig community release policy. http.zig follows stable on its default branch and has older compiler branches. zig-clap uses tagged library releases for stable compilers. libxev generally follows stable rather than nightlies.

## Package versions

Keep library versions separate from compiler versions. For these pre-1.0 libraries, document that a new minor release may drop compiler support or change public APIs. Do not encode required compatibility only in SemVer build metadata such as `+zig.0.17`, because that metadata does not affect version precedence.

## Publication order

1. Test and publish the generator fixes and jsonschema.
2. Pin OpenAI to the published generator commit and regenerate from the pinned specification.
3. Test and publish the provider SDKs.
4. Pin zchema and Instructor to the exact published dependency commits.
5. Run fresh-package consumer tests and wait for the supported-platform CI checks.
6. Merge reviewed branches. Create immutable version tags with manifest versions that match, then publish GitHub release notes.

No release tags are created merely because a version field has been updated. Upgrade PRs are marked ready for review, without merging or publishing releases. Commit pins from upgrade branches remain immutable even if branch tips later move, but they should be merged before those commits become the advertised release set.

Commit remote dependency URLs and hashes generated by Zig 0.17. Keep package fingerprints unchanged. Include every required source, generated asset, test input, and license in package paths. Do not publish temporary sibling path dependencies.

## Changes worth adopting now

The schema libraries must use Zig 0.17 reflection field-name, field-type, and field-attribute arrays. Metadata declarations such as `pub const jsonschema` must be public, because `@hasDecl` no longer exposes private declarations. Treat this as a compatibility migration rather than an opportunity to redesign public schema APIs.

Use `addPassthruArgs` instead of the removed `Build.args`. Expose the generator CLI as a named build path because its executable and static library share an artifact name. Build generators for the host, while compiling generated clients for the requested target. Keep network regeneration opt-in. Generate named parameter structs for optional query and header parameters, so callers can pass `.{}` rather than a growing list of positional null values.

Continue passing allocators and `std.Io` explicitly. Applications should control the I/O runtime, cancellation, and credentials. Avoid hidden environment reads or an internal runtime in reusable SDKs.

Use owned responses and explicit borrowed callback lifetimes. Preserve HTTP error bodies. Bound untrusted HTTP bodies and SSE events. Do not swallow cancellation errors. Compile real SDK calls as well as running model serialization tests, because Zig analyzes functions lazily.

Keep model names open strings. Preserve unknown response variants as JSON. Use typed unions where the specification provides a reliable discriminator. Prefer a JSON escape hatch over an incorrect empty struct.

Pin specifications separately from SDK versions. Record the upstream commit and checksum, and verify them before generation. OpenAI's Stainless endpoint returned HTTP 522 during this upgrade, so regeneration now uses its official GitHub JSON specification.

Anthropic requires native Messages requests, not OpenAI request shapes. Current structured output uses `output_config.format`; strict tool inputs are JSON objects. Its remote schema subset is narrower than local validation. Preserve local constraints when relaxing the schema sent to the provider.

## Verification and limits

Run formatting, Debug and ReleaseSafe tests, examples, and fresh-package consumer builds. Native Linux and macOS CI is configured for the core packages. Cross-compilation is not the same as executing tests on another platform.

Provider tests are offline unless explicitly stated otherwise. No live OpenAI or Anthropic request has been made in this upgrade. Do not claim live API compatibility from serialization tests alone.

Anthropic's full bundled specification exposed generator defects. The fixes allow the full spec to generate without handwritten edits to SDK output. The OpenAI, Anthropic, and Open Responses SDKs all compile their generated endpoint declarations and example calls. Regeneration from pinned inputs is unchanged byte for byte.

The generated SDKs still lack multipart and form encoding. Non-streaming response bodies are buffered without a size bound. Open Responses WebSockets are not implemented. These limits are documented rather than hidden behind a claim of complete transport support.
